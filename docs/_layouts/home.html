Wiring you can read at 3am.

Servo resolves your Go application's object graph from constructor signatures at build time, and emits plain Go source that constructs, starts, supervises, and shuts the whole thing down in dependency order.

No reflection.No runtime registry.No init().No hand-written wiring.

The generated file is ordinary Go

Compiler-checked, IDE-navigable, steppable in a debugger, and reviewable in a pull request. You write constructors; servo writes the part you'd otherwise maintain by hand.

You write

Why build-time

Errors at compile time

A missing provider, an ambiguous binding, or a dependency cycle is a build failure with a source position — not a nil pointer at 3am.

Nothing to step over

No container, no reflection, no registry to inspect. The debugger walks straight through ordinary constructor calls.

Ordered lifecycle

Start-up runs in dependency order with rollback on failure; shutdown runs in reverse, under a budget, reporting what refused to stop.

Reviewable diffs

The generated file is committed. Changing a constructor signature shows up as a readable diff, and servo check fails CI when it goes stale.

Building a microservice with servo

Eighteen chapters that build one real order-management service from an empty directory: HTTP API, JWT auth, Postgres, Redis, NATS, metrics, tracing, a circuit breaker, three levels of tests, CI/CD, and a Docker deployment. Every code block is copied from a real module you can run at every step.
